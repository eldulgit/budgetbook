# BudgetBook

수입과 지출을 기록하고 월별 소비 현황을 확인할 수 있는 개인 가계부 웹 애플리케이션입니다.

Spring Boot 기반의 웹 애플리케이션을 직접 설계하고 구현하며
**Spring MVC의 요청 처리 흐름, JPA를 이용한 데이터 처리, DB 연동, Validation 및 예외 처리까지 백엔드 개발의 전체 흐름을 학습하는 것**을 목표로 제작했습니다.

---

## 프로젝트 개요

가계부의 핵심 기능인 수입·지출 관리를 중심으로 내역 조회, 카테고리 관리, 검색 및 통계 기능을 구현했습니다.

처음 기능을 구현한 뒤에는 코드를 다시 점검하면서 단순히 동작하는 것에 그치지 않고,

* Entity와 Form 객체의 역할 분리
* 입력값 Validation
* Enum을 이용한 데이터 제한
* 예외 처리 구조 개선
* 금액 처리 방식 개선

등을 적용하며 코드 구조를 개선했습니다.

```text

     ↓

     ↓

     ↓
```

# 개발 과정에서 개선한 내용

## 1. Entity와 Form 객체 분리

### 문제

초기에는 Entity를 사용자 입력값을 전달받는 객체로도 사용했습니다.

이 경우 화면의 입력 형식과 데이터베이스에서 관리하는 객체가 직접 연결되기 때문에 두 객체의 책임이 섞이는 문제가 있었습니다.

### 개선

등록과 수정에 사용되는 별도의 Form 객체를 만들었습니다.

```text
사용자 입력
    ↓
Form
    ↓
Controller
    ↓
Service
    ↓
Entity
```

이를 통해 사용자 입력 데이터와 영속성 객체의 역할을 분리했습니다.

---

## 2. Bean Validation을 이용한 입력값 검증

금액이나 필수 입력값이 잘못 들어오는 경우를 방지하기 위해 Validation을 적용했습니다.

Controller에서는 검증 결과를 확인하여 잘못된 값이 입력된 경우 DB에 저장하지 않고 다시 입력 화면으로 이동하도록 처리했습니다.

이를 통해 데이터가 저장되기 전에 사용자 입력값을 검증할 수 있도록 개선했습니다.

---

## 3. 문자열 값을 Enum으로 변경

수입과 지출처럼 사용할 수 있는 값이 정해져 있는 데이터를 처음에는 문자열로 관리했습니다.

문자열을 사용할 경우 오타나 예상하지 못한 값이 저장될 가능성이 있기 때문에 Enum으로 변경했습니다.

```text
INCOME
EXPENSE
```

이를 통해 사용할 수 있는 값을 코드 수준에서 제한했습니다.

---

## 4. Optional 처리 개선

Repository의 `findById()` 결과가 존재하지 않을 경우 단순히 `null`을 반환하도록 처리했던 코드를 수정했습니다.

데이터가 존재하지 않는 상황을 명확한 예외로 처리하도록 변경하여 이후 코드에서 발생할 수 있는 `NullPointerException` 가능성을 줄였습니다.

---

## 5. 전역 예외 처리 적용

각 Controller에서 개별적으로 예외를 처리하면 동일한 코드가 반복될 수 있다고 판단했습니다.

따라서 공통적으로 처리할 수 있는 예외를 전역 예외 처리 방식으로 분리했습니다.

이를 통해

```text
Controller → 요청 처리
Exception Handler → 예외 처리
```

와 같이 책임을 분리했습니다.

---

## 6. 금액 처리 방식 개선

가계부에서는 금액의 정확성이 중요하기 때문에 금액을 다루는 방식을 다시 점검했습니다.

수입과 지출 데이터가 등록부터 조회 및 통계 계산까지 일관된 방식으로 처리될 수 있도록 수정했습니다.

---

## 7. 카테고리 삭제 오류 수정

카테고리를 삭제하는 과정에서 삭제 로직이 두 번 실행되는 문제를 발견했습니다.

Controller → Service → Repository의 호출 흐름을 다시 확인하여 중복 실행되는 부분을 수정했습니다.

이 과정에서 화면에서 발생한 문제를 단순히 View 영역만 확인하는 것이 아니라, 요청부터 DB 처리까지 전체 흐름을 추적하는 경험을 할 수 있었습니다.

---

## 8. DB 접속 정보 분리

DB 아이디와 비밀번호 등의 설정값이 Git 저장소에 노출되지 않도록 애플리케이션 코드와 별도로 관리하도록 수정했습니다.

GitHub에 프로젝트를 공개할 때 중요한 설정 정보를 코드에서 분리해야 한다는 점을 학습했습니다.

# 통계 처리

가계부에 등록된 데이터를 기반으로 선택한 월의 소비 현황을 확인할 수 있도록 구현했습니다.

```text
가계부 데이터
    ↓
Repository 조회
    ↓
Service
    ↓
수입 / 지출 집계
    ↓
Controller
    ↓
통계 화면
```

단순히 내역을 출력하는 것에서 끝내지 않고 저장된 데이터를 다시 조회하고 가공하여 사용자에게 의미 있는 정보를 제공하는 과정을 구현했습니다.

통계 화면에서는 다음 데이터를 확인할 수 있습니다.

* 해당 월의 총 수입
* 해당 월의 총 지출
* 수입 - 지출 잔액
* 카테고리별 지출
* 일별 지출 데이터

# 프로젝트를 통해 학습한 점

이번 프로젝트에서 가장 중점을 둔 부분은 **Spring 웹 애플리케이션에서 데이터가 어떤 과정을 거쳐 처리되는지를 직접 이해하는 것**이었습니다.

하나의 내역을 등록하는 기능을 구현하면서

```text
사용자 입력
    ↓
HTML Form
    ↓
Controller
    ↓
Service
    ↓
Repository
    ↓
JPA
    ↓
Database
```

의 흐름을 직접 구현했습니다.

조회 과정에서는 반대로

```text
Database
    ↓
Repository
    ↓
Service
    ↓
Controller
    ↓
Thymeleaf
    ↓
사용자 화면
```

으로 데이터가 전달되는 과정을 경험했습니다.

또한 처음 작성한 코드를 그대로 두지 않고 다시 검토하면서 Entity/Form 분리, Validation, Enum, 예외 처리 등의 개선 작업을 진행했습니다.

이를 통해 단순히 기능을 구현하는 것뿐 아니라 **각 계층의 역할과 책임을 나누고 유지보수하기 쉬운 구조를 고민하는 과정 역시 중요하다는 것을 학습했습니다.**
